## D1 读写额度消耗

以下为当前实现使用本地 workerd/D1 测得的 `meta.rows_read`、`meta.rows_written`，不是线上账单实测。测试使用不带二级索引的 `changes` 表、每批上传 10 条、每页下载 100 条；业务记录之间没有重复变更，也没有冲突、并发修改或失败重试。造数和初始化开销不计入结果。线上实际消耗以 Cloudflare 统计为准。

D1 按实际读取和写入的行数计量，不按 API 请求数或最终业务记录数计量。索引维护、自增序号维护、变更日志和设备状态也会产生开销；上传同时消耗读取额度，下载也会少量写入设备状态。参见 [D1 官方计费规则](https://developers.cloudflare.com/d1/platform/pricing/)。

### 单批请求实测

| 操作 | 业务数量 | rows_read | rows_written |
| --- | ---: | ---: | ---: |
| 创建新记录 | 10 条 | 43 | 41 |
| 更新已有记录 | 10 条 | 73 | 31 |
| 原样重放最近一次已成功写请求 | 10 条 | 1 | 0 |
| 增量下载不重复记录 | 100 条 | 205 | 1 |
| 已追平后的空增量请求 | 0 条 | 6 | 1 |
| 增量下载最后一条变化 | 1 条 | 7 | 1 |

因此，满批创建新记录约消耗 **4.3 倍读取、4.1 倍写入**；更新已有记录约消耗 **7.3 倍读取、3.1 倍写入**。批次未满时，固定开销分摊到每条记录会更多，不能把这些倍数当作所有请求的固定比例。

创建 10 条的 41 次写入包括：`data` 数据及主键索引 20 次、`changes` 日志及自增序号维护 20 次、设备请求回执 1 次。普通下载约两倍读取，是因为先读取主键或变更日志，再按主键读取数据，另加设备状态、日志边界等检查。

### 15,000 条数据的消耗

| 操作 | rows_read | rows_written | 数据依据 |
| --- | ---: | ---: | --- |
| 上传全新记录，1,500 批 | 64,500 | 61,500 | 按单批实测线性估算 |
| 更新已有记录，1,500 批 | 109,500 | 46,500 | 按单批实测线性估算 |
| 完整下载，150 页 | 31,198 | 150 | 完整分页实测 |
| 增量下载 15,000 条不重复变化，150 页 | 30,750 | 150 | 完整分页实测 |

完整下载约为 **2.08 倍读取**，上述增量下载约为 **2.05 倍读取**。同一页内重复主键会合并，日志条数与返回的业务记录数不一定相同；不同分页大小和数据分布也会改变比例。

**同步自身变化仍消耗读取额度。** 当前 Worker 先读取记录，再按最后修改设备过滤。实测拉取本设备产生的 15,000 条变化时，即使返回 0 条业务记录，仍消耗 30,750 次读取和 150 次写入。

JSEhViewer 首次上传 15,000 条全新记录后，还会拉取上述自身变化，因此这两部分合计约为 **95,250 次读取、61,650 次写入**。此估算不包括注册、上传前的同步、最终游标确认、Cron 日志清理，以及其他设备或请求的用量。

按当前免费版每天 5,000,000 次读取、100,000 次写入计算，这两部分分别约占 **1.91% 读取额度、61.65% 写入额度**。免费额度每天 UTC 00:00（北京时间 08:00）重置，具体额度及计量口径以 [Cloudflare 官方文档](https://developers.cloudflare.com/d1/platform/pricing/) 为准。

## 本地开发

需要 Node.js 22 或更新版本。

```sh
npm ci
cp .dev.vars.example .dev.vars
```

在 GitHub Pages 引导页本地生成主密钥，填入 `.dev.vars` 的 MASTER_KEY。此文件已被 Git 忽略；不得提交真实密钥。

```sh
npm run db:migrate:local
npm run dev
```

默认本地地址为 `http://localhost:8787`。健康检查为 `/v1/health`；其余请求携带 `Authorization: Bearer <MASTER_KEY>`。本地开发和测试使用本地 D1，不连接远端数据库。

```sh
npm run check
```

该命令运行类型检查、workerd/D1 集成测试与部署打包检查，不发布 Worker。测试使用独立数据库和固定测试凭据，不读取个人密钥。

## 部署

项目仍处于开发阶段，未发布给用户；最终表结构直接维护在 `migrations/0001_initial.sql`，不保留旧开发版本的兼容升级迁移。部署使用新建数据库，已有开发数据库不会因修改初始迁移而自动更新。

GitHub Pages 的 Deploy to Cloudflare 流程可预配 DB，并要求输入 MASTER_KEY Secret。构建部署命令使用 `npm run deploy`，先按 DB binding 应用迁移，再部署 Worker。

手动部署时先创建新数据库：

```sh
npx wrangler d1 create cloudflare-d1-sync
```

将返回的 database_id 写入 `wrangler.jsonc` 对应 DB binding，然后执行：

```sh
npm run deploy
npx wrangler secret put MASTER_KEY
```

Secret 缺失时鉴权请求不会通过。设置完成后检查健康接口，再注册设备并验证写入与同步。D1 预配和 Secret 的一键部署行为依据 [Cloudflare 部署按钮文档](https://developers.cloudflare.com/workers/platform/deploy-buttons/)；本仓库本次只做本地验证，未执行远端部署或全新账号部署验收。

Cron 每分钟最多清理十个小页，每页最多删除 100 条过期 change。查询禁止全表扫描；完整下载按主键索引逐页读取，每页最多 100 条，写请求最多 10 条。data 与 tombstone 不自动删除。
