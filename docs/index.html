工作原理

服务端时间不决定冲突，版本号才决定。

客户端保留本地数据库和待提交操作；Worker 用实体版本处理并发，用全局流水做增量拉取。

01

本地先写

用户操作先在客户端事务中写入本地镜像与 pending ops，网络断开也不丢失意图。

02

原子提交

最多 8 个 operation 与 change 流水、幂等记录在同一个 D1 batch 中全成或全败。

03

安全追平

增量游标过期时，完整同步固定截止水位，在暂存区追平后一次性切换。

部署指南

从空账户到第一个同步请求。

部署流程自动预配 D1、应用迁移并绑定 Worker。你只需要保管一个主密钥。

  1. 1

    生成并保存主密钥

    在下方浏览器本地生成 256-bit 密钥，立即存入密码管理器。

  2. 2

    启动 Cloudflare 部署

    部署页会克隆仓库、自动创建 D1，并要求把主密钥填写为 Worker Secret。

  3. 3

    检查健康端点

    部署完成后访问 GET /v1/health，确认返回 API 版本 1。

  4. 4

    绑定第一台设备

    调用 POST /v1/devices/bind，随后带上 X-Device-ID 开始同步。

主密钥

只在此刻、此浏览器内存在。

密钥由浏览器 Web Crypto 生成，不会上传、持久化或写入 URL。刷新或离开页面后，本页无法恢复它。

  • ✓ 32 个随机字节，64 位小写十六进制
  • ✓ 不写入 localStorage、Cookie 或 IndexedDB
  • ✓ 泄露时替换 Secret，全部设备重新配置
