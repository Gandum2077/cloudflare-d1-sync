# 后端实现说明

## 1. 代码入口

| 文件 | 职责 |
| --- | --- |
| `src/index.ts` | HTTP 路由、鉴权与限流入口、Cron |
| `src/body.ts` | 流式 JSON 校验、重复键检查、原始正文 hash、无损 content 数字 |
| `src/http.ts` | 类型校验、错误响应、主密钥比较 |

## 2. 批量事务

先读取设备幂等状态和最多十条记录的版本，不读取旧 content。根据该快照计算各项业务结果。

随后 D1 batch 在同一事务内：复核设备启用状态、请求编号、每个主键的存在性和版本；写入成功项；追加 change；保存整批请求结果。任一复核不符通过 SQLite 的整数溢出表达式使事务失败，避免将“影响 0 行”误当成回滚。

复核冲突时重新读取并判定，最多尝试两次；持续竞争返回 503，客户端原样重试。事务性数据库错误不消费请求编号。业务失败则与其他结果一起保存，即使整批业务失败也消费编号。

主键版本在服务端所有成功修改中单调增加，无法出现删除重建后版本归零导致的旧快照误匹配。部署者不得绕过服务直接修改业务表或幂等字段。

## 3. 读取路径

请求通过 D1 `first-primary` Session 开始，后续读取遵循顺序一致性。增量的设备状态、日志端点与事件页放在同一个 batch 中读取，避免 GC 在边界校验和取页之间清掉事件。

事件只在内存中的当前页内合并。当前记录使用小型 VALUES 请求键集合与 data CROSS JOIN，固定请求键为外层，内层通过复合主键索引查找。最多十个键一组，不进行整表关联扫描。

完整下载按复合主键取键页，再分组点查内容。默认页长 100；内容响应流每次处理最多十条，避免一次保存整页大内容。分页游标字段在完整 JSON 响应的尾部输出；发生晚期额度错误时，响应以顶层 error 结束且不返回成功游标；其他晚期数据库错误仍中断流。客户端必须先检查 error，不得应用半页或推进游标。

批量读取复用十键一组的点查流，按请求索引补齐 found=false 项，保留重复键和顺序；不需要 LEFT JOIN 或扫描缺失记录。单表下载通过 tablename 等值与 id 范围限定主键页，下一页检查同样限制在目标表内。两者返回更新时间与修改设备，只更新设备活动时间，不确认 last_seq。

这些读取是当前状态，不是跨请求快照。D1 Session 不等于全量下载快照，客户端仍需 start_seq 后的恢复补拉。

## 4. 无计数表的日志清理

新实现的每条成功 change 显式使用当前索引末端 seq + 1，在写事务内分配；失败事务回滚。清理仅删最旧前缀，保留最新事件。这保证本实现生成的事件连续；客户端仍不得假定 seq 连续或用 seq + limit 翻页。

清理截止位置为：

```text
cutoff = floor(latest_seq / 5000) * 5000 - 50000
```

到达 55000 时 cutoff=5000；清理追平后保留 50000 条。到达下一个 5000 事件检查点前，保留数量在 50000～54999 之间。cutoff 从最新事件计算，因此清理可以跨 Cron 调用恢复，无需 sync_meta、COUNT(*) 或 GC 会话。

Cron 每分钟读取一次索引末端，然后执行最多十次删除，每次仅选择 seq <= cutoff 的最旧 100 条。到达 cutoff 或本次执行预算后停止。写入不触发全表检查；若写入过快或 Cron 停顿，清理可能暂时积压，保留数量不是瞬时硬上限。

该准确条数推导只对服务自身生成的连续事件成立；不支持外部手动插入跳号、清空日志、删除中间记录或改写数据库。同步协议的游标处理仍容忍间隙。

## 5. 内容与资源边界

不增加协议 content 大小上限。流式解析遇到超过 D1 当前字符串/行硬容量的值会返回 413，其余行开销由 D1 校验。content 数字按原始词法保存，不经 Number 再序列化；如 9007199254740993 和 1e400 可以原样储存和下载。客户端自身的数值处理仍取决于客户端 JSON 库。

请求 hash 逐块计算，包含原始空白与字段顺序；不包含 Authorization。重复键被拒绝，包括转义后相同的键。仅业务 content 是不透明数据，协议字段仍严格校验。

主密钥经 SHA-256 固定长度摘要与 timingSafeEqual 比较。API 不记录请求正文、鉴权头或数据库错误内容。Cloudflare 原生限流绑定默认每来源 IP 每分钟约 120 次，返回 429 和 Retry-After；它是边缘局部限流，不是全局严格计数。健康检查不查询 D1。

## 6. 验证范围

自动化测试运行在本地 workerd 的 D1 模拟实现，覆盖 HTTP、并发写入、实际事务回滚、流式 JSON、完整下载、日志清理，以及不同表规模下的执行计划和 rows_read。

本地数据规模测试包含 1000、10000 行读取和 55000 条日志清理。测试夹具的大量造数与清空操作只属于本地测试，不进入 Worker 运行路径。

远端 D1 的实际性能、读取计费与全新账号一键部署尚未验收。未执行远端 SQL、迁移或部署。

## 7. 写入额度与索引设计

`changes` 的运行时访问只使用 `seq` 主键：增量页、端点查询、序号分配和日志清理均不需要二级索引。初始迁移直接创建这一最终结构，避免维护无用索引的写入开销。

本地 workerd/D1 实测，每批创建 10 条记录的 `rows_written` 从 61 降到 41：data 及主键索引 20、changes 及自增序号维护 20、设备请求回执 1。15,000 条首次上传约从 91,500 降到 61,500，另加注册、下载分页更新设备状态等开销。已有记录更新每批 10 条为 31。相同请求的幂等重试不重新写入。

项目未发布给用户，不提供旧开发数据库的兼容升级。修改初始迁移不会自动改变已经应用过该迁移的开发数据库。
